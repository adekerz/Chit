# Chit — контекст для продолжения разработки

Личный цифровой блокнот официанта. Не связан с iiko API — все отметки
(«пробито», «отдано», «пречек») ставит сам официант вручную; это внутренняя
замена бумажным чекам, не интеграция с POS.

Стек: один файл `index.html` (vanilla JS, без сборки, без зависимостей),
`manifest.json` + `sw.js` для PWA. Осознанно без фреймворка — ставился приоритет
на «быстро запустить и проверить в реальной смене», а не на архитектуру про запас.

## Почему так, а не иначе (решения, которые не стоит откатывать не подумав)

- **Без API iiko принципиально.** У ресторана нет доступа к API. Значит двойной
  ввод (блокнот → потом руками в айку) — это постоянная плата, а не временный
  компромисс. Из этого следует главный критерий качества: скорость ввода важнее
  любой фичи. Если новая фича замедляет тап-путь до добавления блюда — она того
  не стоит.

- **Кнопка «Пробить всё» на уровне стола, а не пробитие по одной позиции.**
  Официант пробивает заказ в айке целиком одним походом к терминалу, не бегает
  после каждого блюда. Одна кнопка — один таймстамп на все непробитые позиции.
  Точечное «П» на позиции оставлено для случаев дозаказа/довозки после основного
  пробития.

- **Хранение данных: `window.storage` (Claude-артефакт) с фолбэком на
  `localStorage` (реальный хостинг).** См. функцию `store` в начале `<script>`.
  На Vercel работает только localStorage-ветка — значит данные живут в браузере
  конкретного телефона, без синка между устройствами. iOS может почистить
  localStorage у сайтов без активности ~7 дней; установка на домашний экран
  снижает риск, но не убирает.

- **Пуш-уведомления о готовности — с жёстким ограничением iOS.** Пока PWA открыт
  на экране — звук/вибро/баннер срабатывают точно по таймеру. При заблокированном
  экране iOS останавливает JS, поэтому таймер не «выстрелит» сам — сигнал придёт
  при следующем открытии приложения (см. `checkReady()` + слушатель
  `visibilitychange`). Обойти без своего Web Push сервера нельзя — это платформенное
  ограничение, не баг кода. Не тратить время на попытки «починить» это без бэкенда.

- **Время готовки (`~минуты` в формате меню) может переопределяться вариантом
  модификатора** (`rare~12` vs `well done~22`) — см. `cookMinutes()`. Базовое
  время у блюда — дефолт, если модификатор не выбран или у него нет своего `~`.

- **Стоп-листы не автоматические.** Официант выставляет их вручную в начале
  смены на отдельном экране (`renderStop`). Никакой синхронизации с кухней нет
  и не планировалась — попытки её добавить без API бессмысленны.

## Формат данных меню/зала — текстовый DSL, не JSON

Парсится функциями `parseMenu()` / `parseTables()`. Формат специально сделан
человекочитаемым для правки прямо в текстовом поле настроек на телефоне, без
JSON-редактора. Если будешь усложнять формат — сохраняй readability, это фича,
не долг.

## Что ещё не проверено в реальной смене (открытые вопросы)

- Времена готовки в демо-меню — не настоящие, ставились «от балды». Если на
  практике сигнал будет систематически приходить раньше/позже реальной
  готовности — обсуждалась идея глобального коэффициента (например ×1.3 в
  запар), а не правка каждого блюда вручную.
- Не проверено, устраивает ли скорость навигации по иерархии меню по сравнению
  с поиском — если поиск окажется быстрее, стоит сделать его стартовым экраном
  меню с автофокусом клавиатуры, а дерево категорий убрать во вторую очередь.
- Название приложения — **Chit** (талон заказа на кухню), выбрано за точность
  термина и краткость под иконкой. Не переименовывать не глядя в код: `manifest.json`
  и `<title>`/`apple-mobile-web-app-title` в `index.html` должны совпадать.

## Обновление: аллергены, вино, объёмы, сервисный сбор (реальное меню KÖK)

Меню/бар/вино заменены на реальные данные ресторана из PDF (`Main menu`, `Bar menu`,
`Breakfast menu`, `Wine card`) и `Пособие для официантов.xlsx`. Дизайн-PDF читались
рендером страниц в изображения (pdftotext/pypdf давали перемешанный текст из-за
многоколоночной вёрстки) — цены и составы сверены визуально.

### Новые токены DSL блюда (после цены, порядок любой, различаются по первому символу)
`Название | цена | ~время | !обяз | ?необяз | @аллергены | $вино`
- `@аллерген, аллерген` → массив `d.allergens`. Источник — колонка «Аллергены» в
  Пособии (авторитет), НЕ угадывание по ингредиентам.
- `$текст` → строка `d.wine` (одна строка «что предложить»). Для кухни это бокальное
  вино из «По бокалам» Пособия = первая страница Wine card (Wines by Glass).
- Вариант модификатора теперь `label~время~цена` — цена варианта переопределяет базовую
  (см. `dishPrice()`), используется для объёмов бара (San Pellegrino 0.25/0.75,
  разливное пиво 0.35/0.5). База таких позиций `| 0 |`, объём — обязательный модификатор.

### Поиск
`matches()` — тонкая обёртка над `textMatch(n,q)`. Добавлен `matchesAllergen(dish,q)`:
поиск по `dish.allergens` тем же алгоритмом. В меню и стоп-листе фильтр
`matches(d.name,q) || matchesAllergen(d,q)` — «кунжут» находит блюда, где кунжут аллерген.

### Сервисный сбор
`S.serviceFee` (%, по умолчанию 10, редактируется в настройках рядом с порогом «висит долго»).
`subtotal()` — сумма позиций, `serviceAmount()` — сбор, `total()` = подытог + сбор.
В счёте стола и при закрытии сбор показан отдельной строкой (не спрятан внутри итога).

### Экран-справочник бутылочного вина
`WINE_CARD` (текстовый DSL, `parseWine()`) + `renderWine()`, кнопка «Вино» на экране зала.
~90 бутылок по цвету/стране/сорту с поиском (`textMatch` по названию/стране/сорту).
Справочник отдельный, в объект блюда не встраивается.

### Важно про данные
`DEFAULT_MENU` применяется только при ПУСТОМ хранилище. Если на устройстве уже сохранено
старое меню (`floor-v2` в localStorage), новое дефолтное меню не подхватится само —
нужно вставить его текст в Настройки → Меню (или очистить localStorage). Аллергены из
Пособия перед реальной сменой стоит перепроверить глазами — это зона безопасности.


## Обновление: автообновление PWA, подтверждение пробития, пейринг вин к блюдам

### PWA не обновлялся сам по себе
Причина в связке двух вещей: `sw.js` не менялся между деплоями (менялся только
`index.html`), поэтому браузер не находил повода переустановить service worker и
раз закэшированный `index.html` в стратегии cache-first отдавался вечно. Плюс
`sw.js` пытался закэшировать несуществующий `icon-180.png` — `caches.addAll` при
любом 404 проваливает весь `install` целиком, то есть SW местами вообще не
переустанавливался. Файл `icon-180.png` добавлен (ресайз из icon-192).
Стратегия в `sw.js` поменяна: для HTML/manifest — network-first с офлайн-фолбэком
на кэш (правило «работать в подвале без связи» сохранено), для иконок — как раньше
кэш-первый. В `index.html` при смене контроллера SW (`controllerchange`) страница
сама перезагружается один раз — так новая версия подхватывается без ручного
удаления с домашнего экрана.

### Подтверждение пробития: стол + что пробито
`punchAll()` и точечное «П» на позиции теперь зовут `showPunchCard(table, items)` —
всплывающая карточка внизу экрана 3.2с с номером стола и списком пробитых позиций
(зачёркнуто, по аналогии с айкой). Раньше был только счётчик «Пробито позиций: N»
без указания стола и состава — на слух в шумном зале этого было мало.

### Пейринг вина к блюдам (Пособие для официантов)
Старое поле `$вино` в DSL меню (`d.wine`) — это только «что налить по бокалам»,
одна строка, без объяснения «почему» и без бутылочных вариантов. Реальный пейринг
из Пособия («По бокалам» + «почему» + 2 бутылочных варианта + «почему» на каждый)
хранится отдельно от строки меню — не стал утяжелять и без того длинные строки
DSL блюда лишним текстом на телефоне. Формат — `PAIRING_TEXT`, парсится
`parsePairings()`: `# Название блюда` (должно совпадать с именем в меню, слаг тот
же), `~вино | почему` — бокал, `*вино | почему` — бутылочный вариант (0–2 раза).
Сопоставлено вручную с 37 блюдами меню (не все совпадали дословно с названиями из
Пособия — сверено по составу).

Доступ к пейрингу — по требованию, не мешая обзору меню:
- иконка 🍷 у блюда в списке меню (только если пейринг есть) → открывает шторку
  с бокалом/бутылками и обоснованием;
- та же иконка у уже добавленной позиции в заказе стола (в `.flags`, рядом с «П»/«О»);
- в шторке добавления блюда с модификаторами — «подробнее →» разворачивает пейринг
  на месте, не теряя выбранные модификаторы/количество.
Если структурированного пейринга для блюда нет — используется старый `d.wine` как
раньше, ничего не сломано для остальных ~200 позиций меню.

### Меню при добавлении блюда — шторка снизу, а не отдельный экран
Раньше «+ Блюдо» переключал `S.screen` на отдельный полноэкранный `renderMenu` —
список позиций стола (пробито/не пробито) при этом пропадал с экрана целиком, пока
официант ищет блюдо. Теперь `S.screen` остаётся `'table'`, а меню — это
`renderMenuDrawer()`, выезжающая снизу шторка высотой не больше `56vh`
(`.menudrawer`, без затемняющего scrim): верх экрана со списком позиций стола
остаётся виден и обновляется как обычно. Триггер — флаг `S.menuOpen`, а не смена
экрана.

Важный нюанс: секундный таймер (`setInterval` внизу файла) раньше безусловно
перерисовывал весь экран на `'table'`, что стирало бы фокус/ввод в поисковой
строке шторки каждую секунду. Добавлен в тот же guard, что уже был у `S.sheet`
(`if((S.sheet || S.menuOpen) && !changed) return;`) — таймеры позиций на экране
стола при открытой шторке не тикают вживую (как и раньше при открытом sheet),
но это тот же компромисс, что уже был принят для модалок, не новый.

Если блюдо требует модификатор (прожарка и т.п.) — открывается обычный `S.sheet`
(`.scrim`+`.sheet`), который по z-index (65) выше шторки (55) и полностью
перекрывает её до подтверждения выбора. После добавления шторка не закрывается
сама — официант продолжает добавлять блюда, пока не нажмёт «Готово».

## Обновление: подкатегории-аккордеон, очистка поиска, скролл карточки пробития, реальный live-patch вместо full re-render

### Категории меню — двухуровневый аккордеон, заметнее визуально
«Салаты и закуски» разделены на `## Закуски` и `## Салаты` в `DEFAULT_MENU` (были
одной кучей — искать конкретную группу для подсказки гостю было дольше). Заголовок
`# категории` (`.cat>.head`) сделан крупнее/жирнее с акцентной полосой слева —
раньше визуально не отличался от подкатегории. Подкатегории (`## `) теперь тоже
сворачиваются отдельно (`.subhead`, состояние `S.openSubs[cat+'|'+sub]`) — раньше
открытие категории сразу разворачивало все её подкатегории одним длинным списком.

### Кнопка «×» у поиска
Общий хелпер `searchBox(placeholder, value, onChange)` (рядом с `el`/`esc`) — обёртка
`.searchwrap` с `input.search` и кнопкой `.searchclear`, видимой только когда есть
текст. Переиспользован во всех трёх местах с поиском: шторка меню, стоп-лист,
винная карта — раньше в каждом был свой инлайновый `<input>` без очистки.

### Карточка пробития — скролл, если позиций много
`.punchcard` теперь `max-height:40vh; overflow-y:auto` вместо неограниченной высоты —
при пробитии большого стола (10+ позиций разом) список не вылезал бы за экран без
возможности долистать. Шапка карточки прилипает (`position:sticky`) при скролле.

### Реальный live-patch вместо render() раз в секунду
Комментарий `«patch text only, never rebuild DOM»` над секундным таймером был
неправдой — код всегда делал полный `render()` экрана `'table'`/`'floor'` каждую
секунду (пересборка всего DOM: все позиции стола или вся сетка столов, включая
навешивание обработчиков заново). На слабом телефоне это ощутимая тряска именно
там, где важна скорость тапа перед гостем. Добавлен `patchLiveTimers()` —
точечно обновляет только текст таймеров (`.tmr` у позиции, время в `.tcell`,
`.rb-w` в ready-баре, `#tbl-elapsed` в шапке стола) и класс `.item` (готово/висит),
не трогая остальной DOM. Полный `render()` в тике остаётся только когда
`checkReady()` реально нашёл готовую позицию (`changed`) или после возврата из
фона (`gap>20000`) — тогда действительно нужен пересчёт бейджей/статусов.
Логика вынесена в `itemLiveState(i)`, общую для `itemRow()` (первая отрисовка) и
`patchLiveTimers()` (точечный патч) — не дублировать формулы таймера.

Заодно убран двойной `render()` при пробитии: `punchAll()`/точечное «П» раньше
рендерили один раз сами и ещё раз внутри `showPunchCard()` — теперь только
`showPunchCard()` (она и так всегда рендерит после установки `S.punchCard`).

Проверено Playwright-тестом: после пробития DOM-узел позиции с меткой
(`data-marker`) переживает несколько тиков таймера подряд (значит идёт патч, а не
пересборка) — как только рядом нет ни одного одноразового таймера тоста/карточки.

## Обновление: стоп-лист вставкой текста из группы

Стопы приходят сообщением в рабочую группу — забивать их по одному в начале смены
долго. Кнопка «Вставить текстом» на экране стопов открывает шторку
(`S.sheet.type==='stoptext'`): вставил сообщение как есть → `parseStopText()`
разбирает его построчно и показывает предпросмотр, «Поставить стоп (N)» применяет.

Как разбирается (`cleanStopLine` + `findDishByText` + `parseStopText`):
- срезаются маркеры списка, нумерация, эмодзи, шапка «Стоп-лист на сегодня»,
  приветствия (`STOP_NOISE`), хвосты «— нет», «(осталось 2)», «2 шт»;
- строка сначала пробуется целиком — иначе развалились бы названия с запятой
  внутри («Томаты ким чи, кунжут ким чи»). Только если целиком не совпало строго,
  строка режется по `,` `;` `/` и « и » и каждый кусок ищется отдельно;
- совпадение — по границам слов (`hasWords`), а НЕ через `textMatch`. Нечёткий
  поиск по подпоследовательности хорош для поиска блюда рукой, но для стопа он
  опасен: «мск» встало бы стопом на «Масала». Здесь цена ошибки — неверная
  информация гостю, поэтому лучше не угадать, чем угадать неправильно.

Важно про кириллицу в регулярках: в JS `\b` и `\w` — только ASCII, на «Стоп-лист»
и «порции» они молча не срабатывают. Поэтому границы слов ищутся через дополнение
строки пробелами (`hasWords`), а вместо `\w+` стоит `[а-яё]+`.

Три исхода, все показываются до применения:
- **распознано** → зелёный блок, список блюд (только эти и уйдут в стоп);
- **непонятно, что именно** (несколько кандидатов: «фри» → Картофель фри / Батат
  фри, «сибас» → аква пацца / целиком) → янтарное предупреждение, стоп НЕ ставится;
- **нет в меню** («Осьминог на гриле») → янтарное предупреждение с просьбой
  проверить название или добавить позицию в меню.

Чекбокс «сначала снять текущие стопы» — для вставки полного списка в начале смены
(по умолчанию выключен, чтобы дневной апдейт просто добавлялся). Предпросмотр
перерисовывается точечно на `oninput`, без `render()` — иначе фокус в поле слетал
бы на каждом символе.

### Тот же разбор: ограничения, гоу, группы, вино, опечатки
Реальное сообщение из группы оказалось сложнее одного списка стопов — вот на что
опирается разбор (пример в плейсхолдере поля):

- **Секции меняют режим.** `detectSection()`: строка с «ОГРАНИЧЕНИЕ»/«ЛИМИТ» →
  дальше лимиты, «СТОП» → стопы, «ГОУ» → гоу. Заголовком считается только строка,
  от которой после вычитания служебных слов ничего не остаётся (или остаётся
  «кухня»/«бар») — иначе «Рибай — стоп» тоже сошёл бы за заголовок.
- **Количество → лимит.** «Щеки с пюре 6 порций» → лимит 6. Единица (порц/шт)
  обязательна: без неё «Ballantine's 17» превратилось бы в лимит 17.
- **Заголовки-группы задают область.** «Текила:», «Пиво бутылочное:» ищутся среди
  подкатегорий меню по огрубённым основам слов (`stemW`, 4 буквы) — так «Лимонад»
  находит «Лимонады», а «Пиво разливное» — «Разливное пиво». Область нужна для
  снятия неоднозначности: «Carlsberg» есть и бутылочный, и разливной. Важно: это
  **подсказка, а не фильтр** — в реальном списке Jägermeister написан под «Ликер:»,
  хотя в меню лежит в другой подкатегории, поэтому при промахе поиск идёт по всему
  меню.
- **«Все …» — группа целиком.** «Пиво разливное: все» и «Все авторские коктейли» →
  вся подкатегория; «Beefeater весь» → все позиции с этим словом в названии.
- **Вино.** Половина бар-листа — бутылки, которых в меню нет вообще (они в
  `WINE_CARD`). Поэтому появился `S.wstop` (ключ — `slug(имя)`, значение 0 = стоп,
  N = «осталось N»). Стоп по вину виден и снимается на экране винной карты (тап по
  строке) и в отдельной секции экрана стопов.
- **Опечатки.** В сообщениях их много: «Chateu saint Robert cuvee», «Tenuto sun
  sisto», «Avignonezi montepulchano», «Underaga altazor», «Jagermaster orange».
  `findNear()` считает долю слов строки, для которых нашлось похожее слово в
  названии (`tokenNear` = равенство, общий префикс от 4 букв с обеих сторон, или
  расстояние Левенштейна ≤1–2). Совпали все слова и кандидат один → применяется
  сразу с пометкой «≈». Совпала часть (от половины) → попадает в «похоже на
  опечатку» и ждёт тапа. Несколько кандидатов → «нужно выбрать», варианты чипами,
  приложение не гадает само.

Грабля в `tokenNear`: правило общего префикса сначала требовало 4 буквы только у
одной стороны — и односимвольное слово «h» из «G.H.Mumm» совпадало с «humidor».
Теперь порог от 4 букв с обеих сторон.

Диакритика складывается в латиницу (`DIA`: ä→a и т.д.) — иначе «Jägermeister»
нормализовался в «j germeister» и не находился по «Jagermaster».

## Разбор багов после этих правок (что нашлось и почему это важно помнить)

**Зал перестал краснеть сам по себе.** Это была регрессия от перехода на
`patchLiveTimers()`: в зале патчился только текст времени, а класс ячейки — нет.
Готовность ловит `checkReady()` и делает полный `render()`, но порог «висит долго»
наступает молча, просто по часам, — и стол оставался зелёным до следующей
перерисовки. Правило на будущее: **если состояние меняется само по времени, а не
по событию, его обязан патчить тикер** — сейчас это класс `.tcell` и класс
`.item`. Проверяется тестом: подкладываем позицию, пробитую 59 секунд назад при
`lateMin=1`, и ждём тик, не трогая приложение.

**Область поиска в стоп-листе живёт до конца текста.** Незнакомый заголовок
(«Настойки:») раньше просто игнорировался, и строки под ним продолжали искаться
в предыдущей группе («Текила») — худший вариант, чем поиск по всему меню. Теперь
любой заголовок сбрасывает область. И наоборот: строка «Текила» без двоеточия
теперь тоже считается заголовком, если совпала с подкатегорией и при этом ни одно
блюдо так не называется, — в реальных сообщениях двоеточия ставят не всегда.

**Шторка стоп-листа не закрывается тапом мимо** (`sc.onclick` пропускает
`type==='stoptext'`): потерять вставленный список вместе с выбранными вариантами
дороже, чем лишний раз нажать «Отмена». Остальные шторки закрываются как раньше.

**Превью разбирается с задержкой 200 мс.** Полный разбор бар-листа — около 20 мс
на десктопе и заметно больше на телефоне; считать его на каждую букву при ручной
правке значит подвешивать ввод. Вставка (одно событие) по-прежнему считается сразу.

Проверено сквозным Playwright-прогоном на 16 шагов (стол → заказ → модификаторы →
перенос позиции → пречек → закрытие → стопы → вставка текстом → вино → настройки →
перезагрузка) — без ошибок в консоли, состояние переживает перезагрузку. Плюс
прогон парсера на мусорных входах: пустой текст, одни цифры, голые двоеточия,
эмодзи, строка на 200 повторов, латиница вперемешку с кириллицей.

## Обновление: поиск русскими буквами по латинице и ранжирование выдачи

Половина барной карты на латинице, а официант набирает на русской раскладке:
«авион», «бифитер», «ягер», «джек дэниэлс». Появилось три слоя поверх поиска:

1. **Транслитерация** (`translit`, RU→LAT): «авион» → avion. Детерминированная,
   поэтому в разборе стоп-листа её результат (score 65+) применяется сразу.
2. **Фонетический скелет** (`phon`): транслит + схлопывание удвоений и типовых
   сочетаний (ck→k, ph→f, ee/ea→i, oo/ou→u, j→y, c→k, w→v). Без него «бифитер»
   не сходится с Beefeater: русские пишут на слух, а не по буквам. Сравнение
   пословное, с допуском Левенштейна (`nearPhon` — мягче, чем `tokenNear` в
   разборе стоп-листа: в поиске цена ошибки это лишняя строка в выдаче, а в
   стоп-листе — неверная информация гостю).
3. **Ранжирование** (`searchScore` + `rankDishes`). Подпоследовательность («кпч» →
   капучино) — фича, но именно из-за неё на «авион» вылезал «Бефстроганов из
   говядины»: а-в-и-о-н находились вразброс. Теперь у неё самый низкий вес, и
   если есть совпадения получше (от 60), она вообще не показывается. Внутри
   подпоследовательности учитывается кучность (`subseqSpan`): «кпч» в «капучино»
   плотнее, чем в «паштете из куриной печени», поэтому капучино теперь первый.

В разборе стоп-листа появился тот же слой (`findPhon`), но с разделением: транслит
применяется сам, фонетика только предлагается тапом. Так «Авион» встаёт стопом
сразу, а «Бифитер весь» показывает кандидатов (среди них есть и Luxardo Bitter —
фонетически «биттер» и «бифитер» близки, выбирает человек).

**Выбор вариантов стал множественным.** Раньше на «Domain faiveley joseph» (два
бургундских Faiveley) можно было отметить только один — а в стоп ушли оба.
Теперь чипы в блоке «нужно выбрать» отмечаются независимо.

**«El humidor» — это El Jimador.** Опечаточный слой его не берёт: humidor и
jimador отличаются на три буквы, а порог там два (поднимать опасно). Спасло то,
что в `findNear` перестали отбрасываться двухбуквенные слова — совпадение держится
на «el», даёт половину слов строки и попадает в «похоже на опечатку» с подтверждением.

## Обновление: скорость у стола — экран не уезжает, правки позиции на месте

**Экран уезжал наверх и закрывалась клавиатура.** Каждая перерисовка собирает DOM
заново, поэтому терялись и прокрутка (`main`, список в шторке), и фокус в поиске —
на телефоне это ещё и закрывало клавиатуру прямо посреди набора. Теперь `render()`
снимает прокрутку и фокус до пересборки и возвращает после (позицию курсора тоже).
Правило: **всё, что живёт в DOM, а не в `S`, надо сохранять вокруг `render()`**.

**Клавиатура перекрывала шторку меню.** `position:fixed;bottom:0` на iOS уезжает
под клавиатуру. `fitDrawer()` слушает `visualViewport` и поднимает шторку на высоту
клавиатуры, заодно ужимая её по реально видимой области (при открытой клавиатуре
отдаём шторке больше — 72% вместо 56%, всё равно верх экрана уже занят).

**Тост воровал тапы.** Он висел внизу поверх списка блюд и полторы секунды
перехватывал нажатия. Стал `pointer-events:none`, а при открытой шторке уходит
наверх, чтобы вообще не ложиться на список.

**Поле поиска очищается после добавления** (`afterAdd`): следующее блюдо набирается
с нуля, фокус остаётся в поле, клавиатура между позициями не закрывается.

**Правки позиции — прямо в строке заказа**: −/+ количества, ✕ удаления и сумма.
Удаление непробитой позиции происходит сразу (свежая опечатка), пробитой — только
после подтверждения (её уже готовят). Тап по остальной части строки по-прежнему
открывает карточку, тап по кнопкам — нет (`e.target.closest('.qrow')`).

**Стол: пересадка и удаление.** Тап по заголовку «Стол N ▾» открывает шторку:
пересадить заказ на любой свободный номер (ключ в `S.orders` меняется вместе с
`o.table` и `S.activeTable`), сменить число гостей, удалить стол целиком — для
случая «открыл не тот» или «уже не актуально». Удаление всегда с подтверждением и
показывает, сколько позиций и на какую сумму сгорит.

**Быстрые комментарии** (`QUICK_COMMENTS`) — чипы «без лука / соус отдельно /
подать позже / аллергия!» в карточке блюда и при добавлении. Тап добавляет или
убирает фразу из строки комментария, своё по-прежнему можно вписать руками.

**Кнопка «Обновить приложение» в настройках.** Установленный на экран PWA
продолжал открывать старую версию, и приходилось переустанавливать через Safari.
Причин две, обе закрыты:
- браузер отдавал сам `sw.js` из HTTP-кэша и до суток не видел новую версию —
  регистрация теперь с `updateViaCache:'none'` плюс `reg.update()` сразу на старте;
- когда это всё же случилось, выйти из залипшего состояния было нечем. `hardUpdate()`
  снимает все service worker'ы, чистит Cache Storage и грузится заново с
  `?u=<время>`, чтобы не поймать страницу из HTTP-кэша. `localStorage` не трогаем —
  там открытые столы, стопы и настройки смены (проверено тестом: до и после
  обновления состояние совпадает). Офлайн кнопка отказывается работать: снести
  кэш без сети значит остаться вообще без приложения.

Рядом показывается `APP_VERSION` — по ней видно, доехало обновление или нет.
**Её нужно поднимать при каждом деплое**, иначе смысл теряется.

**Одинаковые номера столов в разных зонах — это разные столы.** Заказ лежал в
`S.orders` под голым номером, поэтому «1» в основном зале и «1» в лаундже были
одним и тем же ключом: открываешь один — загорается и второй. Ключ теперь
`зона|номер` (`tkey`), сам номер хранится в `o.table`, зона в `o.zone`, ключ
продублирован в `o.key` (по нему возвращаются из строки «готово — забрать»).
`migrateTableKeys()` на старте переводит уже сохранённые заказы на новый ключ,
иначе после обновления открытые столы потерялись бы. Номер зоны в подписи
показывается только когда такой номер есть в нескольких зонах (`tableLabel`) —
иначе «Стол 1 · Основной зал» мозолил бы глаза там, где номер и так уникален.

**Пустой стол закрывается одной кнопкой** в нижней панели, без пречека и галочек:
случай «открыл не тот стол» не должен стоить четырёх тапов. Кнопка появляется
только когда позиций нет — терять нечего, подтверждение не спрашиваем.

**Пробитая позиция подтягивается к верху экрана.** При открытой шторке с
клавиатурой от заказа остаётся узкая полоса сверху, и было непонятно, что именно
пробилось. Теперь действие ставит `S.scrollTo=<id позиции>`, а `render()` после
восстановления прокрутки поднимает эту строку к верху и подсвечивает её
(`.item.flash`). Работает на точечном «П», на «Пробить всё» (к первой пробитой) и
на добавлении блюда — новая позиция тоже видна сразу, а не за шторкой.

Чтобы прокрутка могла поднять к верху даже последнюю позицию, `main` на экране
стола получает запас снизу в три четверти экрана — и со шторкой, и без неё. Без
запаса прокрутка упирается в конец списка: при открытой шторке нижние строки
навсегда прятались за ней, а при закрытой пробитая позиция просто оставалась на
месте и казалось, что скролл не работает.

Карточка подтверждения пробития при открытой шторке заменяется тостом: иначе она
ложится на поиск. Сам тост в этом режиме встаёт в просвет между заказом и шторкой
(`--drawer-h`), чтобы не закрывать ни подсвеченную позицию сверху, ни список снизу.

**Комментарий — кнопкой прямо в строке заказа.** Быстрые фразы уже были, но только
внутри карточки блюда, а у блюда без модификаторов карточка не открывается при
добавлении — до комментариев никто не доходил. Теперь в строке есть 💬 (подсвечена,
если комментарий есть) и отдельная компактная шторка `type:'comment'`.

**Времена готовки подняты в полтора раза** (стейки — до 24–38 минут по прожарке):
по факту смены сигнал приходил раньше, чем блюдо реально отдавали. Важно: правка
лежит в `DEFAULT_MENU`, а он применяется только при пустом хранилище — на телефоне
уже сохранена старая копия. Поэтому в настройках появилась кнопка **«Сбросить к
встроенному»**: без неё обновления меню из приложения до устройства не доезжают.
